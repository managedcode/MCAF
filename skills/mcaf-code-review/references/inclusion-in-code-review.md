# Review Communication

Make findings understandable and evidence-based without judging the author.

- Describe the concrete trigger, incorrect behavior, impact, and relevant code.
- Distinguish a blocking defect or accepted requirement from an optional preference.
- Apply the same technical standard regardless of seniority, identity, or authorship.
- Use the repository's formatter/style rules instead of debating personal taste.
- Ask a specific technical question when the contract is unclear; do not invent a defect.
- Keep feedback respectful and direct. Forced compliments, personal criticism, and speculative psychological explanations do not help a reviewer assess code.
- Resolve disagreements through source, requirements, and evidence. Required corrections must not be softened into optional suggestions.
- Authors should explain the decision, address substantiated findings, and update code/tests/docs together where needed.

Communicating a finding in chat does not authorize posting it to an external review or notifying teammates.
