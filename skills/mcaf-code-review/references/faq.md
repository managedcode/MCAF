# Review Process Decisions

## Large Changes

Make one coherent accepted scope reviewable through clear requirements, entry points, and a focused diff. Split independent changes when useful, but do not silently omit requested behavior or leave unapproved partial delivery. For human prioritization of a large generated area, use `mcaf-human-review-planning`.

## Early Feedback

Draft PRs and reviews outside PRs can both support early feedback. Use the team's existing flow; a PR is not necessarily a completed or approved change.

## Slow Reviews

Identify the actual ownership or queue bottleneck before adding process. A concrete reviewer/turnaround agreement may help; changing external assignments or sending notifications needs authorization.

## Review Enforcement

Use the repository's protections, required reviewers, and quality gates. Pairing, worker self-review, or a green test run does not waive a required independent review or authorize bypassing protections.
